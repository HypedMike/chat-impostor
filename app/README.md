# Chat-alayzer — Frontend

React + TypeScript + Vite app implementing the game UI and flow. See the [repo root README](../README.md) for the overall project (there's no separate backend — this app talks to an in-browser WASM module, documented in [rust-analyzer/README.md](../rust-analyzer/README.md)).

## Stack

- **React 19** + **TypeScript**
- **Vite 8** (dev server / build)
- **Tailwind CSS v4** (via `@tailwindcss/vite`, imported once in `src/index.css`) for all styling — no CSS modules or styled-components
- **Zustand** for the single game store
- **Oxlint** for linting (`pnpm lint`)

## Commands

```bash
pnpm install
pnpm dev       # start Vite dev server with HMR
pnpm build     # tsc -b (typecheck all project references) + vite build
pnpm preview   # serve the production build locally
pnpm lint      # oxlint
```

There is only one route/screen tree: `App` → `OnboardingView`, which itself renders either the setup UI or `ShowResults`, switching on `started` from the store. There is no router.

## State: `game_store.ts`

All game state lives in one Zustand store (`useGameStore`), read via the hook in `OnboardingView` and passed down to components as props — components themselves are stateless w.r.t. game data (aside from local UI state like an input's current text).

State shape:

- `players: (Player & { impostor: boolean })[]`
- `started: boolean` — flips the view from setup to results
- `word` / `impostorWord: string` — the two possible secret words for this round
- `chatImported: boolean` — gates the Start button
- `impostorCount: number`, `impostorsKnow: boolean` — game config

Key actions:

- `importChatExport(content)` — feeds raw chat text to the wasm engine (`services/analyzer.ts`) and marks `chatImported`.
- `pickWord()` — asks the engine for a word twice (word + impostor word), retrying the second pick up to 5 times if it collides with the first; falls back to the same word if it can't find a different one.
- `pickImpostor()` — Fisher–Yates shuffles player indices and flags the first `impostorCount` (clamped to `[1, players.length - 1]`) as impostors. Re-running this reassigns roles from scratch.
- `startGame()` / `resetGame()` — toggle `started`; `resetGame` clears impostor flags and words but keeps the player list, so you can replay with the same group.

The typical call sequence, from `OnboardingView.handleGameStart`, is: `pickWord()` → `pickImpostor()` → `startGame()`.

## Engine boundary: `services/analyzer.ts`

`import_chat`/`pick_word` are synchronous Rust functions under the hood, but the wasm module itself needs an async `init()` before first use. `analyzer.ts` memoizes that init promise (`ensureReady`) so any number of calls to `importChatExport`/`pickWord` before or after init all wait on the same single initialization, then delegates straight to the generated bindings in `../wasm/chat_alayzer`. This file is the only place in the frontend that imports from `wasm/`.

## Components

- **`ImportChat`** — a plain `<input type="file" accept=".txt">`; reads the file as text client-side (`file.text()`) and hands it to `importChatExport`. Shows "Chat imported" once `imported` is true. Nothing is uploaded anywhere.
- **`AddPlayers`** — controlled text input; Enter or the Add button calls `addPlayer` with `{ id: crypto.randomUUID(), name }` and clears the input. Ignores blank/whitespace-only names.
- **`PlayerList`** — read-only list of name pills; renders nothing when empty.
- **`GameConfig`** — number input for impostor count (clamped to `[1, players.length - 1]`, disabled implicitly by the max when there's only 1 player) and a checkbox for `impostorsKnow`.
- **`ShowResults`** — the reveal flow once the round has started. Cycles through `players` one at a time (`currentIndex` local state); each player must tap "Tap to reveal" (`lifted` local state) before "Next player"/"Done" is enabled. What's revealed depends on `impostorsKnow`:
  - if `impostorsKnow` is on and this player is an impostor → "You are the impostor!"
  - otherwise → the actual word (`impostorWord` for impostors, `word` for everyone else) — so when `impostorsKnow` is off, impostors just see a different word without being told why, which is the intended "figure it out" mode.
  When every player has gone through, it shows a "Play again" button wired to `resetGame`.

## Adding a new game step or screen

Given there's no router, a new screen is just another branch in `OnboardingView` (or a new view composed the same way) switching on store state — follow the existing pattern of keeping components presentational and putting state transitions in `game_store.ts` actions rather than in component event handlers.
